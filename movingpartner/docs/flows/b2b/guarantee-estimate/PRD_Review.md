> **한 줄 정의**: 고객이 남긴 리뷰에 대해 파트너가 **답글 1개를 작성·수정·삭제**할 수 있고, 부적절하다고 판단한 리뷰는 **숨김을 요청**할 수 있다. 운영팀은 어드민에서 숨김 요청을 검토해 숨김 처리하며, 처리 완료 시 파트너는 **앱 푸시 알림**을 받는다.

---

## 1. 배경 & 문제 정의

### 1.1 배경 — 리뷰탭의 현재 상태

리뷰탭은 데스크탑 TopNav에만 노출되는 Feature Flag(`reviews`) 화면으로, 현재는 **조회 전용 stub**이다(`사장님센터_이사_기존IA_사용자흐름.md` §5). 파트너는 고객이 남긴 리뷰를 볼 수 있을 뿐, 어떤 응대나 조치도 할 수 없다.

```
고객 리뷰 작성(오늘의집 앱) ─▶ 리뷰탭 노출(조회만) ─▶ ✕ 파트너 응대 수단 없음
                                                        ↑
                                              파트너-고객 커뮤니케이션 단절 지점
```

이사 서비스는 고가·1회성·분쟁 민감도가 높은 거래라 리뷰 한 건이 파트너의 신규 매칭에 직접적인 영향을 준다. 그러나 파트너는 (1) 오해·사실관계를 해명할 공개 채널이 없고, (2) 명백히 허위이거나 욕설·개인정보가 포함된 리뷰에 대해서도 **자체적으로 조치를 요청할 경로가 없다**.

### 1.2 문제 정의

| # | 문제 | 누가 겪는가 | 비즈니스 영향 |
|---|---|---|---|
| **R-1 응대 채널 부재** | 부정 리뷰·오해성 리뷰에 파트너가 공개적으로 해명·사과할 수단이 없음 | 파트너(핵심) · 고객 | 신뢰 회복 기회 상실 · 매칭 전환 하락 · 일방적 평판 노출 |
| **R-2 부적절 리뷰 방치** | 허위·욕설·개인정보 노출·경쟁사 비방 등 정책 위반 리뷰에 대한 신고/숨김 경로 없음 | 파트너 · 운영팀 | 정책 위반 리뷰 상시 노출 · 운영 수기 처리 · 분쟁 비용 |
| **R-3 처리 결과 불투명** | 숨김을 요청해도(현재는 CS 채널) 처리 여부·결과를 파트너가 알 수 없음 | 파트너 · 운영팀 | 중복 문의 · 운영 응대 비용 · 파트너 불만 |

**핵심 제약(설계 전제)**
숨김은 **파트너 일방으로 즉시 실행되어선 안 된다**. 부정 리뷰를 파트너가 임의로 가릴 수 있으면 리뷰 신뢰도 자체가 무너진다. 따라서 숨김은 **파트너 요청 → 운영팀 검토 → 처리**의 게이트 구조를 가지며, 답글만 파트너가 직접 게시한다.

### 1.3 솔루션 방향

**목표 상태**: 리뷰탭을 조회 전용에서 **응대 가능한 작업 공간**으로 확장한다. 답글은 파트너가 직접, 숨김은 운영 검토 게이트를 거쳐 처리하고, 결과는 알림으로 닫는다.

```
[파트너]                              [운영팀=어드민]            [고객]
리뷰 확인(리뷰탭)
 ├─ 답글 작성/수정/삭제 ───────────────────────────────────▶ 고객 앱 리뷰 하단 노출
 └─ 숨김 요청(사유 선택) ──────────▶ 숨김 요청 큐 검토
                                       ├ 승인 ─▶ 리뷰 숨김 처리 ─▶ 고객 앱 비노출
                                       │         └─▶ [앱 푸시] 파트너에게 숨김완료 알림
                                       └ 반려 ─▶ 사유와 함께 요청 종료(노출 유지)
```

**P0에서 제공하는 솔루션**

| 문제 | P0 솔루션 |
|---|---|
| R-1 응대 채널 | 리뷰당 **답글 1개** 작성 · 작성 후 **수정/삭제** 가능 · 고객 앱 리뷰 하단 노출 |
| R-2 부적절 리뷰 | 리뷰별 **숨김 요청**(사유 선택+상세) → 어드민 숨김 요청 큐로 적재 |
| R-3 처리 결과 | 어드민 **승인 시 숨김 처리** + 파트너에게 **앱 푸시 숨김완료 알림** / 반려 시 사유 회신 |

**의도적으로 P0 밖에 두는 것**
답글 금칙어·욕설 자동 필터 · 답글 다중 작성/스레드 · 고객의 답글 재반박 · 숨김 자동 판정(AI) · 이메일/SMS 알림 · 평점(별점) 자체 정정 — 연계만 정의하거나 차기 과제로 이연.

## 2. 목표 & 성공 지표

**목표**
- **R-1 해소**: 파트너가 리뷰에 공개적으로 응대할 수 있는 표준 채널 제공(답글 1개·수정·삭제).
- **R-2·R-3 해소**: 부적절 리뷰를 정책 게이트(요청→검토→처리)로 처리하고, 결과를 파트너에게 알림으로 닫는다.

**성공 지표(초안)**
- 리뷰 답글 작성률(전체 리뷰 대비 답글 달린 비율)
- 부정 리뷰(예: 3점 이하) 답글 작성률
- 숨김 요청 → 운영 처리 소요시간(SLA) · 승인/반려율
- 숨김완료 알림 도달률·확인율
- 숨김 **오남용 가드레일**: 반려율 급증·동일 파트너 반복 요청 모니터링

## 3. 사용자 & 시나리오

- **파트너 · 답글(메인)**: 좋은 리뷰엔 감사 답글, 오해성 리뷰엔 사실관계 해명 답글을 작성. 오타·과한 표현은 수정하거나 삭제.
- **파트너 · 숨김 요청**: 욕설·허위·개인정보 노출 리뷰를 발견 → 사유 선택 후 숨김 요청. 처리 결과를 알림으로 확인.
- **운영팀 · 숨김 검토(어드민)**: 숨김 요청 큐에서 리뷰 원문·요청 사유를 검토 → 정책 부합 시 숨김 처리, 아니면 반려.

## 6. 리뷰 카드 & 상태 모델 (신규)

**리뷰 카드 구성**
- 헤더: 별점 · 고객명(마스킹) · 작성일 · 오더(이사 종류·예정일) 연결 정보
- 바디: 리뷰 본문 · 첨부 사진(있을 경우)
- 답글 영역: 파트너 답글(있으면 표시) / 없으면 `답글 작성` CTA
- 액션(조건부): `답글 작성`(답글 없을 때) · `답글 수정`/`답글 삭제`(답글 있을 때) · `숨김 요청`(노출 상태 + 미요청 상태일 때)

**리뷰 상태(REVIEW_STATUS)**

| 상태 | 카드 뱃지 | 고객 앱 노출 | 파트너 액션 |
|---|---|---|---|
| `visible` (노출중) | 없음 | 노출 | 답글·숨김요청 가능 |
| `hide_requested` (숨김요청됨) | `숨김 검토중`(gray) | 노출 유지 | 답글 가능 · 숨김요청 **중복 불가** |
| `hidden` (숨김완료) | `숨김 처리됨`(gray-weak) | **비노출** | 답글 비활성(안내 문구) |
| `hide_rejected` (요청반려) | `요청 반려`(gray) | 노출 | 답글 가능 · 숨김요청 재요청 가능 |

**답글 상태(REPLY_STATUS)**: `none`(미작성) → `posted`(게시됨) → (`posted` 상태에서 수정/삭제) → 삭제 시 `none` 복귀.

## 7. 기능 ① 리뷰 답글 (P0)

### 7-1. 핵심 규칙
- **리뷰 1건당 답글 1개**. 이미 답글이 있으면 `답글 작성` 대신 `수정`/`삭제`만 노출.
- 작성 직후 고객 앱 리뷰 하단에 **"사장님 답글"** 형태로 노출(노출 위치·형식은 고객 앱 연계 — 본 PRD는 게시·동기화만 정의).
- 숨김완료(`hidden`) 상태의 리뷰에는 답글 작성·수정 불가(이미 작성된 답글은 리뷰와 함께 비노출).

### 7-2. 플로우
```
리뷰 카드 [답글 작성]
 ① 답글 입력 모달/인라인 (텍스트, 글자수 제한 안내)
 ② [등록] → 확인 → 게시 (REPLY_STATUS: none → posted)
 ③ 고객 앱 리뷰 하단 노출(동기화)

작성 후:
 [답글 수정] → 입력 모달(기존 답글 프리필) → [저장] → 갱신
 [답글 삭제] → 확인 다이얼로그("답글을 삭제할까요?") → 삭제(REPLY_STATUS: posted → none)
```

### 7-3. 요구사항
- FR-RP1: 리뷰당 답글 1개 제약(서버 검증). 답글 존재 시 작성 CTA 숨김.
- FR-RP2: 글자수 제한(예: 1,000자) 및 잔여 글자수 표시. 빈 답글·공백만 입력 차단.
- FR-RP3: 답글 수정 시 기존 내용 프리필, 저장 시 갱신. 수정 이력은 백엔드 보관(노출은 최신본).
- FR-RP4: 답글 삭제는 확인 다이얼로그 후 실행. 삭제 시 고객 앱에서도 즉시 비노출.
- FR-RP5: `hidden` 상태 리뷰는 답글 액션 비활성 + 안내 문구("숨김 처리된 리뷰입니다").
- FR-RP6: 답글 작성/수정/삭제 후 토스트 피드백.

## 8. 기능 ② 리뷰 숨김 요청 → 운영 처리 (P0)

### 8-1. 전체 여정 (역할 핸드오프)
```
[파트너]                          [운영팀=어드민]               [고객 앱]
① 리뷰 카드 [숨김 요청]
② 사유 선택 + 상세 입력
③ 요청 제출 ───────발송───────▶ ④ 숨김 요청 큐 적재(검토 대기)
   (REVIEW_STATUS: hide_requested)   ⑤ 리뷰 원문·사유 검토
                                       ├ 승인 ─▶ ⑥ 숨김 처리 ───────▶ 리뷰 비노출
                                       │         (REVIEW_STATUS: hidden)
                                       │         └─▶ ⑦ [앱 푸시] 숨김완료 알림 → 파트너
                                       └ 반려 ─▶ 사유 기록(REVIEW_STATUS: hide_rejected)
                                                 → 노출 유지 · 재요청 가능
```
> 숨김 요청 중(`hide_requested`)에도 리뷰는 **고객 앱에 계속 노출**된다. 비노출은 운영 승인(`hidden`) 시점부터.

### 8-2. 파트너 — 숨김 요청
- 진입: 리뷰 카드 `숨김 요청` (상태 `visible` 또는 `hide_rejected`일 때만).
- 사유 선택(택1, 예시): `허위 사실` · `욕설/비방` · `개인정보 노출` · `리뷰와 무관한 내용` · `경쟁사/광고` · `기타`.
- 상세 사유 입력(필수, 예: 최소 10자) → 증빙 첨부(선택, P1).
- 제출 후 카드 뱃지 `숨김 검토중`, `숨김 요청` CTA 비활성(중복 요청 차단).

**요구사항**
- FR-HQ1: `visible`/`hide_rejected` 상태에서만 숨김 요청 가능. `hide_requested`/`hidden`은 CTA 비활성.
- FR-HQ2: 사유 택1 필수 + 상세 사유 필수. 미입력 시 제출 불가.
- FR-HQ3: 제출 시 REVIEW_STATUS `hide_requested` 전이 + 어드민 큐 적재.
- FR-HQ4: 동일 리뷰 중복 요청 차단. 반려 후에는 재요청 허용.

### 8-3. 운영팀(어드민) — 숨김 요청 검토
- 위치: 어드민 `리뷰 관리 > 숨김 요청` 큐. 검토 대기 건 우선 정렬.
- 큐 항목: 리뷰 원문·별점·고객/오더 정보 · 파트너 요청 사유(분류+상세) · 요청 일시 · 파트너 정보.
- 액션: **승인(숨김 처리)** / **반려**(사유 입력) / 보류(메모).

**요구사항**
- FR-AD1: 숨김 요청 목록·상세 조회(필터: 대기/승인/반려, 검색: 파트너·오더).
- FR-AD2: 승인 시 REVIEW_STATUS `hidden` 전이 → 고객 앱 비노출 + 파트너 앱 푸시 발송 트리거.
- FR-AD3: 반려 시 REVIEW_STATUS `hide_rejected` 전이 + 반려 사유 기록(노출 유지). 반려 알림은 P1.
- FR-AD4: 처리자·처리일시·사유 감사 로그 보존(분쟁 대비).
- FR-AD5: 동일 리뷰 다중 요청·반복 요청에 대한 운영 가시화(오남용 모니터링).
- FR-AD6: 승인/반려 판단은 **§8-4 블라인드 운영 정책 기준**에 따른다. 기준 외 사유(예: 단순 저평점·아쉬움 토로)는 반려.

### 8-4. 리뷰 블라인드(숨김) 운영 정책 — 승인/반려 판단 기준

운영팀이 숨김 요청을 **승인할 수 있는 유형**을 아래로 한정한다. 정당한 불만·솔직한 저평점 후기는 보호하고, 정책 위반에 해당하는 경우에만 숨김(블라인드) 처리한다. 본 기준은 고객 안내 페이지(`리뷰_숨김정책_고객안내_텍스트.md`)와 동일한 분류를 사용한다.

| 유형 | 리뷰 내용 기준 | 사진 기준 |
|---|---|---|
| **내용 불일치·확인 불가** | 이사 서비스와 무관한 내용 · 자음/모음/특수문자만 나열 · 의미 유추 불가 · 실제 이용 건이 아닌 다른 건/서비스 리뷰 · 이사 작업 평가 없이 무관한 사항만 기재 | 이사 작업과 무관한 사진 · 다른 화면 캡처 · 어떤 작업인지 판별 어려운 사진 · 사진 미포함(사진 필수 영역 한정) |
| **욕설 및 비방** | 욕설·음담패설 포함 · 서비스 평가가 아닌 **업체 비방 목적**의 내용 | — |
| **개인정보** | 본인 또는 타인의 개인정보(이름·연락처·주소 등) 포함 | — |
| **불법·음란물** | — | 신체의 민감한 부위가 노출된 사진 |
| **불쾌감** | — | 상해 등으로 불쾌감을 줄 수 있는 사진 |
| **어뷰징** | 같은 리뷰를 동일인이 반복 등록한 경우 | — |
| **편향된 내용** | 정치적·사회적 논평 · 인종/국적/민족/종교/성별/성 정체성/성적 지향/연령/장애 등을 이유로 한 폭력·증오 유발 내용 | — |
| **기타** | 실제로 이사 서비스를 이용하지 않고 작성된 것으로 확인되는 경우(내용으로 판단) | — |

**운영 원칙**
- **블라인드는 "위반 유형 해당" + "운영 검토 승인"의 2단계를 모두 충족할 때만** 실행. 파트너 일방 숨김 불가(§1.2 핵심 제약).
- **저평점·서비스 불만 자체는 숨김 사유가 아니다.** 욕설·허위·개인정보 등 위 유형에 해당할 때만 승인.
- 부분 위반(예: 일부 문장만 개인정보)인 경우에도 리뷰 단위로 숨김 처리(부분 마스킹은 P1 검토).
- 반려 시 위 유형 중 어디에도 해당하지 않는다는 근거를 사유로 기록(FR-AD3).
- 동일 리뷰 반복 요청·동일 파트너의 정상 리뷰 반복 숨김 시도는 오남용으로 모니터링(FR-AD5).

## 9. 기능 ③ 숨김완료 알림 (P0 · 앱 푸시)

### 9-1. 트리거 & 채널
- **트리거**: 어드민이 숨김 요청을 **승인(REVIEW_STATUS → `hidden`)** 한 시점.
- **채널**: 사장님센터 **앱 푸시**(P0 한정). 인앱 알림센터·이메일/SMS는 범위 외.

### 9-2. 알림 내용(초안)
- 타이틀: `요청하신 리뷰가 숨김 처리되었어요`
- 본문: `[오더명/이사 예정일] 리뷰 숨김 요청이 처리되었습니다. 자세히 보기`
- 딥링크: 리뷰탭 해당 리뷰(또는 처리 결과 상세)로 이동.

### 9-3. 요구사항
- FR-NT1: `hidden` 전이 이벤트를 구독해 해당 리뷰의 요청 파트너에게 푸시 1건 발송.
- FR-NT2: 푸시 수신 동의/디바이스 토큰 없을 경우 발송 스킵(인앱 상태 뱃지로 결과 확인 가능하도록 폴백).
- FR-NT3: 딥링크 탭 시 해당 리뷰로 진입, 카드 뱃지 `숨김 처리됨` 확인.
- FR-NT4: 중복 발송 방지(동일 이벤트 1회).

## 11. IA / 상태 모델 변경

- **신규 탭 추가 없음**: 기존 리뷰탭(`/moving/reviews`) 내부 확장.
- **리뷰 상태 뱃지 신설**: `숨김 검토중` · `숨김 처리됨` · `요청 반려`.
- **카드 액션 추가**: `답글 작성`/`답글 수정`/`답글 삭제` · `숨김 요청`(상태 의존 노출).
- **모바일 노출 정책**: 리뷰탭은 기존 데스크탑 전용. 답글·숨김 요청은 현장(모바일) 사용성이 높아 **모바일 리뷰탭 노출을 검토**(오픈 이슈 §14). P0는 데스크탑 우선, 모바일은 단계적.
- **유지 패턴**: 상태 뱃지 체계 · 카드 액션 버튼 스타일 · pageStates · Feature Flag(`reviews`) 가드.

## 12. 엣지 케이스 & 검증

- **숨김 요청 중 답글**: `hide_requested` 상태에서도 답글은 허용(노출 유지 중이므로). 단 `hidden` 전이 시 답글도 함께 비노출.
- **답글 작성 후 리뷰 숨김 승인**: 답글은 보존하되 고객 앱에서 리뷰와 함께 비노출. 재노출(반려 번복) 시 답글도 복원.
- **반려 후 재요청**: 동일 리뷰 재요청 허용하되 운영이 반복 요청을 인지할 수 있게 이력 노출.
- **푸시 미수신 환경**: 토큰 없음/수신 거부 시 발송 스킵 + 인앱 뱃지로 결과 확인 폴백(FR-NT2).
- **숨김 오남용**: 파트너가 정당한 부정 리뷰를 반복 숨김 요청 → 반려율·반복요청 모니터링(FR-AD5), 정책 위반 시 운영 경고.
- **동시성**: 어드민 처리 직전 파트너가 답글 수정/삭제하는 경합 → 최종 상태 서버 기준 동기화.

## 13. P0 완료 기준 (DoD)
- 리뷰당 답글 1개 작성·수정·삭제가 동작하고 고객 앱 노출/비노출과 동기화된다.
- 숨김 요청(사유+상세) → 어드민 큐 적재 → 승인/반려 게이트가 동작한다.
- 어드민 승인 시 리뷰가 고객 앱에서 비노출되고, 요청 파트너에게 앱 푸시 1건이 발송된다.
- 리뷰 상태 뱃지(검토중/처리됨/반려) 및 액션 노출 조건이 상태별로 정확히 분기한다.

## 14. 오픈 이슈
- 리뷰탭의 **모바일 노출** 여부 및 답글/숨김요청 모바일 UX(현장 사용성 vs 기존 데스크탑 전용 정책).
- 답글 **금칙어·욕설 자동 필터** 도입 시점(P1) 및 운영 수기 모니터링 범위.
- 숨김 **반려 알림(푸시)** 제공 여부(P0는 인앱 상태 표기, P1 푸시).
- 숨김 처리 **SLA**(요청→처리 목표 시간) 및 오남용 가드레일 임계치 정의.
- 숨김 처리된 리뷰가 파트너 평점·매칭 점수에 반영되는지(평점 산정 정책 연계).
- 답글/숨김 처리 데이터의 **분쟁·책임보장 증빙** 효력 범위(법무·운영 협의).
- 블라인드 운영 정책(§8-4) 유형의 **이사 서비스 특화 보강** 필요 여부(예: 작업 전 취소 건·견적만 받은 건 리뷰 처리 기준).
- 부분 위반 리뷰의 **부분 마스킹** 도입 여부(P0는 리뷰 단위 숨김).
