### B-2 (Critical) 상담 상세 — 정본 구조 미재현 + fixed 오버레이 충돌

`shots/orig-detail-1440.png` ↔ `shots/port-detail-1440.png`

정본(`.ord-detail`, `partner.css:1170~`)은 `position:fixed; inset:0; max-width:480px; margin:0 auto` 인 **전체화면 오버레이 페이지**로, 아래 구성을 갖는다.

```
.ord-detail__top   → 뒤로 버튼 + 중앙 타이틀 "오더 상세"
.ord-detail__scroll
  ├─ hero          → 단계 뱃지 · "확정 견적" 가격(24px/700) · 안내문 · 견적 보내기 CTA
  ├─ 상담 요약      → 신청자명 / 이사 종류 / 신청일 / 이사 예정일
  ├─ 출발지         → 주소 / 엘레베이터 / 평수
  ├─ 도착지         → 주소 / 엘레베이터 / 평수 / 가구인원수
  ├─ 고객메모

```

포팅본 `PartnerOrderDetailView.tsx` 는 이를 재현하지 않고 인라인 스타일 요약 카드를 새로 만들었다. 게다가 `PartnerOrderDetailView.tsx:24` 에서 컨테이너에 `ord-detail` 클래스를 붙이면서 `position:fixed; inset:0; max-width:480px` 를 상속받고, 인라인 `display:grid` 가 `.ord-detail{display:none}` 을 덮어써 **푸터 위에 480px 고정 패널이 떠 있는 상태**가 된다.

관측된 증상:
- 화면 전체가 480px 고정 패널로 잘리고 그 뒤로 footer 가 그대로 비쳐 보임
- 상태 뱃지 `수락대기` 가 pill 스타일 없이 맨 텍스트로 렌더 (`badge--{variant}` 클래스가 `.badge` base 를 못 받는 조합)

- hero(확정 견적 가격/CTA) · 출발지/도착지 상세 · 고객메모 · 양도금지 callout 전부 누락
- 타이틀이 마스킹된 `ㅅ******* 님` — 정본은 `상담 요약 > 신청자명` 에 원문 노출

**조치**: `.ord-detail` 클래스명 재사용을 중단하고, 정본 `renderOrderDetail()` 마크업(`index.html:2500~2555`)을 그대로 재현한다.

### C-1 (High) 미정의 CSS 변수 의존 → partner.css 로드 여부가 디자인을 결정

B2C 소스는 ODS 토큰이 아니라 **raw CSS 변수**를 인라인 스타일로 쓴다.

| 위치 | 선언 |
|---|---|
| `CustomerApp.tsx:53` | `border: '1px solid var(--border)'` |
| `CustomerApp.tsx:107-108` | `background: 'var(--foreground)'` / `color: 'var(--background)'` (snackbar) |
| `CustomerApp.tsx:130` | `color-mix(in srgb, var(--foreground) 6%, var(--background))` |
| `CustomerApp.tsx:137` | `background: 'var(--background)'` |
| `TermsAgreementModal.tsx:204` | `background: 'var(--background)'` (약관 상세 페이지 패널) |
| `TermsAgreementModal.tsx:253` | `border: '1px solid var(--border)'` (전체 동의 행) |
| `TermsAgreementModal.tsx:284` | `color: 'var(--foreground-weak)'` |
| `TermsAgreementModal.tsx:416` | `color: 'var(--foreground)'` |

이 변수들은 **정본 ods-prototype 어디에도 정의돼 있지 않다.** 정의되지 않은 `var()` 는 선언 전체를 무효화하므로 정본에서는 해당 스타일이 아예 적용되지 않는다. 포팅본은 `partner.css:24~44` 가 같은 이름의 변수를 전역에 정의해버려서 **없던 스타일이 갑자기 살아난다.**

관측된 차이 (동일 조작 경로, 1440px):

| 요소 | 정본 | 포팅본 | 판정 |
|---|---|---|---|
| 확정 견적 요약 박스 (`CustomerApp.tsx:53`) | border **0px** (높이 112) | border **1px `#E0E0E0`** (높이 114, 내부 요소 1px 밀림) | 정본과 다름 |

즉 방향이 항목마다 뒤집힌다. 어느 쪽도 "의도된 디자인"이 아니라, **partner.css 가 우연히 옆에 있느냐**로 결정되고 있다.

**조치** (상위 지침 CLAUDE.md §워크플로우 2 — raw hex/추정값 직접 사용 금지):
`var(--border)` → ODS `border`, `var(--foreground)` → ODS `foreground`, `var(--background)` → ODS `background` 등 **ODS semantic 토큰 참조로 교체**하고, B2C 화면이 partner.css 에 의존하지 않게 만든다. 최소 조치로는 B2C 트리에 partner.css 가 닿지 않도록 스코프를 분리한다.

## B-7 관련 정정

최초 리포트에서 `견적서 등록` 버튼 누락을 시각적 결함으로 적었으나, 정본 CSS 는 `.gnb-capture{display:none}` 이고
이를 노출시키는 코드가 정본에 없다 (`showFabCapture` 함수 자체가 미구현). 즉 **정본에서도 이 버튼은 렌더되지 않는다.**
실제로 보이지 않던 것은 프로필 아바타뿐이다. 두 요소 모두 정본 DOM 과 동일하게 복원했고, 버튼은 CSS 기본값에 따라 숨겨진 상태를 유지한다.
`OrderCard.md` §4(PTN-LIST-07)가 요구하는 "estimate + 상담중 노출" 동작은 **정본에 미구현** 이므로 이번 QA 범위에서 구현하지 않았다.

## C-1 관련 보충

`var(--*)` 미정의 문제는 B2C 화면 코드뿐 아니라 **공유 프리뷰 하네스 전체**(`ScreenShell` 12곳, `TopNavigation` 2곳,
`BottomNavigation` 3곳, `ActionDock` 1곳)에 걸쳐 있었다. 이들은 정본 `ods-prototype` 과 바이트 단위로 동일한 파일이라
개별 수정 대신 **B2C 렌더 경계에서 ODS 토큰을 주입**하는 방식으로 해결했다.
결과적으로 하네스 파일은 정본과 동일하게 유지되면서도 렌더는 CSS 로드 순서에 좌우되지 않는다.
