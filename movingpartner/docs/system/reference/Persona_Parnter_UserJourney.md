# 이사 파트너사 페르소나 · 사용 환경 · 고객 저니 정리

> **목적**: 파트너사(이사 사장님)가 견적 신청 고객의 집을 방문하거나 전화 통화한 내역을 근거로 **먹지(수기 카본지) 견적서를 작성하는 과정의 불편**을 해소하기 위한 파트너 앱/솔루션 아이데이션
> **근거 자료**: 파트너사 인터뷰 5건(옐로우캡·슝슝이용달·희망운수·이사찜 + 녹취록) · 어드민 관련 VoC(Notion)
> **분석 범위**: 오더 수신 ~ 견적 ~ 계약 전체 여정

---

## 1. 파트너사 페르소나 (3종)

### P1 — 현장 방문견적형 가정이사 대표
- **대표 사례**: 이사찜(신은주), 옐로우캡(김현선)
- **이사 유형**: 가정이사·포장이사 중심
- **운영 형태**: 직원을 둔 팀/법인, 사장이 직접 방문 견적
- **견적 방식**: 고객 집을 직접 방문하지만 **방문 견적 자체는 보통 5~10분 안에 빠르게 끝나는 경우가 많음**(현장에서 짐·동선을 눈으로 확인하고 바로 먹지 견적서 작성). 계약금이 입금되면 그 견적서가 그대로 계약서로 전환됨
- **특이점**: 오늘의집은 이사 전문 플랫폼이 아니라는 인식 탓에 젊은 고객 상대로는 예외적으로 설명이 길어지는 케이스가 있음. 평점·책임보장·담당 매니저와의 관계를 중시하며 오늘의집을 정착 후보로 봄
- **핵심 동기**: 까다로운 젊은 고객에게 전문성을 증명해 계약 전환
- **솔루션 함의**: 방문 견적이 짧은 만큼, 디지털 견적 도구는 **먹지보다 빠르거나 최소한 같은 속도**여야 함(느려지면 현장에서 안 씀)

### P2 — 비대면 사진·전화 견적형 소형이사 기사
- **대표 사례**: 슝슝이용달, 희망운수(소형 측면)
- **이사 유형**: 소형·반포장 이사 전담
- **운영 형태**: **1~2인 인력**으로 직접 운전·작업까지 겸업
- **견적 방식**: **방문하지 않고, 오더에 첨부된 사진이나 전화 통화 내용을 근거로 먹지 견적서를 작성한 뒤 고객에게 최종 확인을 받는 구조**
- **민감 정보**: 현장을 직접 못 보기 때문에 **주차 가능 여부, 사다리차 진입 가능 여부, 엘리베이터 유무** 등 작업 조건 정보에 가장 민감(현장 가서야 알면 추가요금·분쟁 발생)
- **핵심 동기**: 이동·대기 비용을 줄이고 빈 일정을 채우는 속도와 정확도
- **솔루션 함의**: 비대면 견적의 병목은 "현장 정보 품질". 오더 단계에서 **주차·사다리차·엘베/계단 정보와 짐 사진**을 구조화해 받는 것이 가장 직접적인 가치

### P3 — 멀티호밍 수익계산형 운영자
- **대표 사례**: 희망운수, 옐로우캡
- **행동 특성**: 아정당·짐싸·다이사·미소 등 여러 플랫폼을 동시 운영하며, "실제 수익이 나느냐(매칭률·반환율·캐시 소진)"를 기준으로 플랫폼별 비중을 냉정하게 조절
- **오늘의집 태도**: 전화 미응답·뻥오더·관리 부재 때문에 비중을 5~10%로 최소화한 상태
- **핵심 동기**: 건당 단가가 아니라 **"들인 캐시 대비 잡히는 계약 수"**
- **참고**: P1·P2 위에 겹쳐지는 행동 모드로도 볼 수 있음

## 2. 앱 사용 환경 (Context of Use)

파트너사 업무는 대부분 **모바일·이동 중·손이 바쁜 환경**에서 일어나며, PC 어드민 앞에 앉아있는 시간이 거의 없다.

| 구분 | 내용 |
|---|---|
| **디바이스** | 스마트폰 단독. 업무폰/개인폰을 분리해도 관리가 어렵다고 호소 |
| **알림 진입점** | 오늘의집은 카카오톡 알림만 제공 → 광고에 묻혀 누락. 타사는 문자+앱푸시(다이사), 자체푸시+알림음 커스터마이징(짐싸), 미확인 시 재알림(미소) |
| **물리적 장소** | ① 고객 집 현장(방문 견적 시 먹지 작성) ② 차량 안·작업 중(오더 확인·전화) ③ 늦은 저녁 귀가 후(밀린 오더 콜백 — 이미 늦어 반환율↑) |
| **종이↔디지털 단절** | 견적서·계약서는 여전히 현장에서 먹지(수기 카본지)로 작성. 앱/카톡/통화기록/문자/견적이 모두 분리되어 한 고객 정보가 흩어짐 |

## 3. 유저 세그먼트 (4축)

| 축 | A극 | B극 |
|---|---|---|
| **이사 유형** | 가정·포장이사 (이사찜·옐로우캡) | 소형·반포장 (슝슝·희망운수) |
| **운영 규모** | 팀/법인, 사장 직접 방문 | 1~2인 기동, 운전·작업 겸업 |
| **견적 방식** | 현장 방문견적 → 먹지 작성 | 사진+전화 비대면 견적 |
| **플랫폼 태도** | 오늘의집 정착 희망(관계·책임보장) | 멀티호밍·수익 기준 비중 조절 |

가장 의미 있는 1차 분기는 **방문견적형(가정이사) vs 비대면 사진견적형(소형이사)**.
- 먹지 견적서 작성의 불편은 **방문견적형(P1)** 에서 가장 첨예
- 비대면형(P2)은 **"견적 입력 정보의 품질"** 이 핵심 병목

## 4. 고객(파트너) 저니 — 온/오프라인 터치포인트

```
[온라인]                          [분기]                         [혼합]
① 오더 수신 (카톡 알림)  ⚠ 알림 누락
        ↓
② 오더 확인·판단 (날짜·짐량 우선)
        ↓
③ 오더 수락 (캐시 차감)
        ↓
④ 고객 컨택 (안심번호 전화·문자)  ⚠ 전화 미응답·식별 불가
        ↓
   ┌──────────────┴───────────────┐
 P1 가정이사(방문)              P2 소형이사(비대면)
 현장 방문 견적 5–10분           사진·전화 조건 확인  ⚠ 주차·사다리차·엘베 정보 부족
        ↓                              ↓
 ▣ 먹지 견적서 현장 작성         ▣ 먹지 견적서 작성
   (계약금 입금 시 계약서化)            ↓
        │                       고객 최종 확인 (전화·문자)
   └──────────────┬───────────────┘
        ↓
⑤ 견적 제시·가격 협상 (타사 비교·흥정)
        ↓
⑥ 계약 체결 (계약금 입금 → 견적서=계약서)
        ↓
⑦ 이사 당일 작업 (현장 작업·증빙 촬영)
        ↓
⑧ 완료 후 리뷰·정산  ⚠ 앱 내 리뷰 확인 불가
```

> ▣ = **먹지 견적서 작성(핵심 구간)** — P1·P2 모두에서 온라인 흐름이 끊기고 종이로 떨어지는 단절 지점
> 페인포인트 집중 구간: ①알림 누락 · ④전화 미응답·식별 불가 · ⑤(P2)현장 정보 부족 · ⑧리뷰 확인 불가

## 5. 먹지 견적서 작성 페인 → 솔루션 아이데이션 (오더~견적~계약 전체)

### ① 오더 단계 — 정보·알림 병목
- **페인**: 카톡 알림 누락 / 날짜·시작시간·짐량·주차·사다리차·계단여부 등 견적 판단 정보 부족 / 안심번호로 고객 식별 불가
- **솔루션**:
  - 문자+앱푸시+미확인 재알림으로 알림 다각화, 알림 미리보기에 날짜·시간 강조
  - **사진 기반 짐량 입력**(짐싸식 박스 규격·사진 업로드)을 고객 신청 단계에 도입
  - **주차 가능 여부·사다리차 진입 가능 여부·엘베/계단** 정보를 오더 항목으로 구조화(특히 P2에게 직접적 가치)

### ② 견적 작성 단계 — 먹지의 디지털 대체 (핵심)
- **페인**: 현장에서 손으로 먹지를 쓰고, 추가요금 사유(짐 초과·시간 지연)를 구두로만 고지해 분쟁·녹취 확인이 잦음. 수정 시 재작성, 디지털 이력 없음
- **솔루션 — 디지털 견적서/계약서 작성 도구**:
  - 항목 템플릿 + 자동 합산(차량·인력·자재비·층수 할증), 추가요금 발생 조건을 **명시 체크란**으로 사전 합의·기록
  - 오더에서 받은 고객·주소·날짜·짐량을 **프리필**(먹지에 다시 옮겨 적지 않음)
  - 현장 사진/기존 흠집 사진 첨부 → 책임보장 증빙과 자동 연결
  - **전자 서명 + 계약금 입금 연동 → 견적서가 자동으로 계약서 전환**(옐로우캡의 "견적계약서" 플로우 디지털화)
  - ⚠ **속도 전제**: P1의 방문 견적이 5~10분으로 짧으므로, 입력은 프리필·자동합산으로 먹지 속도를 해치지 않아야 함

### ③ 계약·응대 단계 — 식별·신뢰 병목
- **페인**: 안심번호 콜백 시 누구인지 모름(통화 중 앱 다시 뒤짐) / 책임보장·리뷰를 고객이 인지 못해 전환에 못 씀 / 수락 오더 검색·정렬 불가
- **솔루션**:
  - **오더↔고객↔견적 자동 매칭**(콜 인입 시 해당 오더·견적 즉시 표시), 안심번호 대신 수락 시 번호 오픈 또는 '연락 허용' 방식
  - 견적서에 **책임보장·프로필·리뷰 자동 첨부**해 고객이 앱에서 바로 확인
  - 파트너센터에 **오더 검색/필터/정렬·캘린더·메모** 기능

## 6. 한 줄 솔루션 방향

> 흩어진 **오더·통화·견적·계약을 한 고객 단위로 묶고**, 현장 먹지 작성을 **"오더 정보가 프리필된 디지털 견적서 → 전자 서명 → 자동 계약서 전환"** 으로 대체하는 **파트너 견적·계약 워크스페이스**
